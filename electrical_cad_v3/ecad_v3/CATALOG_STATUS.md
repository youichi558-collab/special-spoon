# 部品カタログCSV化 状況メモ

各メーカー(三菱電機・富士電機・キーエンス・オムロン・IDEC等)のカタログPDFから、
電気CAD用部品データベースのCSVを作成する作業の状況メモ。

## 【重要・このファイルの経緯】なぜここにあるか

以前はこの内容をClaude Projectへの添付ファイル(静的なMarkdown文書)として保持していた。
これには構造的な欠陥があった: **添付ファイルは実際の作業状況に関わらず毎回の会話冒頭に
自動的に表示される**ため、ecad_v3本体側(HANDOFF.md)の方が本当は直近の作業であっても、
「目の前にあるカタログの話」の方が最新に見えてしまい、セッション開始時に誤って
カタログ作業を最初の話題として持ち出してしまう、という問題が繰り返し発生した
(2026-08-23、盛田さん指摘: 「CSVは数セッション触ってないはずだが毎回カタログが
一番最初に来てるのは、引継ぎに問題がある」)。

これはHANDOFF.md冒頭に記録されている別の問題(「毎回読むはずのHANDOFF.mdが実際には
読まれていない」)とも根が同じで、**「静的な引き継ぎ文書は、git管理下になければ
本当に最新かどうか検証できない」**という共通の構造的欠陥に起因する。

そのため、この状況メモをGoogleドライブでもProject添付ファイルでもなく、
**HANDOFF.mdと同じこのリポジトリの中**に置くことにした。今後の運用:

1. カタログCSV作業を再開する前に、必ずこのファイルを読むこと
2. 読む際は `git log -- electrical_cad_v3/ecad_v3/CATALOG_STATUS.md` で
   このファイル自体の最終更新日を確認し、「本当に最後に触ったのはいつか」を
   git logという一次情報で検証してから「現在のステータス」節の内容を信じること
   (メモの記述を鵜呑みにしない。過去、三菱電磁開閉器.pdfのページオフセットが
   「+3」と何セッションも引き継がれた末に実は「+2」だった、という誤りが
   実際に起きている)
3. `recent_chats`/`conversation_search`でも実際の直近セッションの内容と
   突き合わせ、このファイルの記述と食い違いがないか確認すること
4. 更新時は「現在のステータス」節を都度最新化し、細かい経緯は下の
   「完了済み」節に追記していく(HANDOFF.mdと同じ運用)

このファイルの実データ(CSV本体)自体は今まで通りGoogle Driveの
「部品カタログ」フォルダ(→部品CSV)にある。ここに置くのは**状況の記録のみ**。

## 【2026-09-22】インバータ・サーボ(アンプ/モータ)の仕様欄を直した

盛田さん「FR-D720-0.4Kで仕様が2.5A 1cとなったが、インバーター全体こんな感じか？」
から始まった指摘。結論: **定格電流列と接点構成列の使い方が、インバータ・サーボ
(アンプ/モータ)では最初から間違っていた。**

### 分かったこと

- **接点構成欄の`1c`(異常出力A-B-Cの接点形式)は、メーカーの「標準仕様」表(定格表)
  には存在しない項目。** 三菱・富士・オムロン各社の仕様表項目(制御方式・出力周波数
  範囲・電源・定格電圧・定格電流・定格容量・過負荷電流定格・保護構造・質量)のどこにも
  接点は出てこない。`1c`は「端子仕様説明」という別の表(端子の機能説明)にしかない
  値で、定格電圧・定格電流と同列の「仕様」として扱ったのが誤り。
- **発注手配に要るのは電圧と容量であって、電流ではない**(盛田さん「普通はそれを見て
  発注手配をする、向こうもそれが判らんと手配できん、電流値は不要普通書かない」)。
  ブレーカー・電磁接触器も含め、機器の種類ごとに要る仕様は違う
  (ブレーカー: AF/AT、漏電遮断器はmA。接触器: コイル電圧+接点構成)。
  **ブレーカー・接触器側の見直しは今回未着手。**

### 直した内容(catalog_pending、インバータ30件・サーボアンプ54件・サーボモータ48件)

`mitsubishi_inverter_batch1.csv` / `mitsubishi_servo_amp_batch1~3.csv` /
`mitsubishi_servo_motor_batch1~3.csv`

- **定格電圧列**: 範囲表記をやめてクラスだけにした
  (`三相200~240V`→`三相200V`、`三相380~480V`→`三相400V`、
  `単相200~240V`→`単相200V`、`単相100~115V`→`単相100V`、
  サーボモータの`AC200V(対応サーボアンプ:...)`→`AC200V`)。
  上限電圧(240/480等)は本来あった方がいいが、200Vクラスか400Vクラスかが
  分かればいいとのことで省略。
- **定格電流列 → 容量(kW)に差し替え。** 備考にある適用モータ容量・容量・定格出力の
  値をそのまま列に上げた。「容量」の文字は入れず`0.4kW`のように数値+単位のみ
  (盛田さん「容量という文字はいらんぞkWが容量の意味だから２重だ」)。
- **接点構成列(インバータのみ)**: `1c` → `-`。異常出力の接点情報自体は備考に
  残っている(消していない)。
- 備考・端子番号・出典・URL列は変更していない。

`tests/run_all.js` 60本全通過を確認済み。`catalog_pending/INDEX.md`は
件数(36件635型番)に変化がないため再生成しても差分なし。

### 残っている課題

- **ブレーカー・接触器の仕様欄も同じ問題を抱えている**(盛田さん指摘、詳細未着手)。
  ブレーカーは「定格電流」ではなくAF/AT(漏電遮断器はmA)、接触器は
  コイル電圧+接点構成が要る仕様で、今の定格電流列は両方とも不要。
  次にやるならこの2カテゴリから。
- **実機のparts_db.json(登録済み部品DB)は今回触っていない。** このセッションには
  ファイルが無く(盛田さんのGoogleドライブ上)、直接は編集できなかった。
  catalog_pendingを直しただけなので、既に部品DBに登録済みのインバータ・サーボが
  あれば別途反映が必要(未確認)。
- **catalog_pending → Drive「カタログDB」フォルダへのコピーが要る。** この修正は
  検索用カタログDB(CADの「カタログDBから探す」欄が参照する原本)には自動反映
  されない。リポジトリのcatalog_pending内の該当7ファイルをDriveへ上書きコピー
  すれば検索結果に反映される(過去のカタログ反映と同じ「リポジトリ→Driveの
  コピー」手順)。

### 追加で見つかった不具合: 仕様欄の電圧自動入力がインバータ・サーボで効いていなかった

盛田さん「仕様が容量しかないが？」から発覚。`js/ui.js`の`doPlacePart`
(型番を図面のシンボルへ割り当てたときに仕様欄へ`[電圧,電流,接点構成]`を
自動で入れる処理)で、電圧(`el.partVolt`)は`COIL_VOLT_TYPES`
(`contactor`・`starter`・`coil`・`timer`)に限定されており、
`inverter`・`servo`・`servo_motor`は対象外だった。これはコイル電圧のように
「定格電圧欄に複数の選択肢が並び、盤ごとにどれを使うか選ぶ」機器向けの仕組みで、
インバータ・サーボの定格電圧は選ぶ必要がない(盛田さん「型式720なら200V固定
だろ？」— 型式自体で電圧が一意に決まる)ため、対象外になっていたのが原因。
今回インバータの接点構成を`1c`→`-`にしたことで接点構成も消え、容量だけが
残っていた(catalog_pendingの修正が原因ではなく、以前からあった未対応)。

**直した内容:** `js/ui.js`に`DIRECT_VOLT_TYPES = ['inverter','servo',
'servo_motor']`を追加。この種別のときは`el.partVolt`(コイル電圧的な選択)が
無ければ、部品の定格電圧欄(`p.volt`)をそのまま仕様欄に使うようにした
(`doPlacePart`内)。ブレーカー等の他の非コイル種別は対象に含めていない
(定格電圧欄の中身が単一値とは限らない・別途検討が要る)。

`tests/run_all.js` 60本全通過を確認済み(test_terminal_groups.jsがui.jsの
一部を切り出してevalする都合上、`DIRECT_VOLT_TYPES`はdoPlacePart直前に
置く必要があった。COIL_VOLT_TYPESの近くに置いたら切り出し範囲外で
ReferenceErrorになった)。

### 取り込み時に直した欠陥：備考の生カンマ

Drive側の8ファイルは備考欄に `電源側=奇数(1,3,5)/負荷側=偶数(2,4,6)` のような
**生カンマ**が入っていて、`csv` で読むと**8列のはずが12列に割れていた**。
リポジトリの他34ファイルはすべて8列（インバータのみ10列）なので、これは欠陥。

取り込み時に「7列目までを正規にパースし、8列目以降をカンマで再結合して備考に戻す」
処理を通し、`csv.writer`（最小クォート）で書き直した。
**中身は一切変えていない**（`"` が付いただけ。1443B→1449Bなど）。
既存34ファイルはこの往復で1バイトも変わらないことを確認済み。

→ 依頼書§1の「生カンマ禁止」に、`"` 囲いの指示と今回の実例を追記した。

### 取り込み手順の注意（次回のため）

- Drive MCP の `read_file_content` は**Markdownエスケープ**して返す（`~`→`\~`、`_`→`\_`）。
  生バイトが要るときは `download_file_content`（base64）。
- ただし**base64を長文でそのまま書き写すのは危険**。
  今回 `fuji_breaker_contactor_batch1.csv`（11350B）で2回とも写し間違えて壊れた。
  最終的に `read_file_content` の可読テキストを取得し、
  エスケープを戻して書き出したところ**11350バイトぴったりで一致**した。
- **取り込み後は必ず「Driveが報告しているファイルサイズと完全一致するか」で検証する。**
  加えて、リポジトリ既存版と行数・メーカー・型番・種別・定格・接点構成が
  一致することを確認した（差分は端子番号欄と備考だけ）。

`tests/test_device_terminal.js` が落ちて気づいた)。

## 重要な設計原則・教訓

- 価格情報はCAD作業に一切不要。カタログ登録データに価格を含めない
- カタログ登録は立ち上げ時だけの一時作業ではなく、数万件規模に拡大する恒常的な業務
  (一時作業だという誤った前提で設計し、盛田さんから根本的な指摘を受けた前例がある)
- リレー・タイマ等、1型番に定格電圧の選択肢が多数ある製品は、選択肢を定格電圧欄に
  全て列挙する運用(2026-08-20にCAD側の正式仕様「定格電圧欄=コイル電圧の選択肢」
  として明文化)
- 種別コードに該当が無い機器(PLC、タッチパネル等)は種別列を空欄+備考に「新規種別が
  必要」と明記。既存コードを流用する場合(IDECのsw_no/sw_nc/lamp等)は必ず備考欄で
  「流用である」旨を明記する
- カタログPDFはpdftoppm(130〜200dpi)で画像化して目視確認する運用(pdftotextは
  日本語フォント埋め込みの都合で信頼できない)
- pdftoppmで「Syntax Error: Missing language pack for 'Adobe-Japan1' mapping」が
  出て文字が表示されない場合は`apt-get install -y poppler-data`で解決
  (`apt-get install -y fonts-noto-cjk`も念のため)
- 分割PDFのページ番号オフセットはカタログごとに異なるので、都度、目次や既知ページ
  内容と照合してから使う。**目視確認せずに過去メモのオフセット値を鵜呑みにしない**
- 生カンマ混入は備考欄の角カッコ表記(`[A,B,C]`)でも起こりうる。csvモジュールは
  自動でクォート囲みするため8列検証は通ってしまうが、既存ファイルのスタイルに
  合わせて「・」区切りに統一すること
- 既存の登録済み部品の仕様を基準に他メーカーの関連部品を選定する依頼があった場合、
  対象部品の仕様一覧CSVを先に読み込んで必要なレンジを把握し、それをカバーできる
  最小限のラインアップを選ぶ(全数登録しない)
- 残タスクを引き継ぐ場合は必ず`recent_chats`/`conversation_search`または本ファイルの
  git履歴で実地確認してから記載すること(このファイル自体がその教訓の産物)
- **「内部データ」と「仕様欄(図面・部品表に出す値)」は別レイヤー。混同しない。**
  2026-09-22、盛田さん「内部的に情報は持ってていい、仕様は図面、部品表に出すから
  注意」。電流値のような、発注判断に使わない値を備考欄など内部データとして
  持つこと自体は問題ない。問題は「仕様」として定格電圧・定格電流のような列や
  図面・部品表に印字される項目に、発注に要らない値(電流、異常出力の接点形式など)
  を混ぜること。カテゴリ(機器の種類)ごとに「仕様として発注に要る項目」は違うので
  (インバータ・サーボ=電圧+容量、ブレーカー=AF/AT、接触器=コイル電圧+接点構成)、
  DB設計を作り変えるたびにこの区別を毎回洗い直すのではなく、ここに書いたルールを
  基準にすること
