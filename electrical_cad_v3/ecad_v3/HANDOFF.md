## プロジェクト概要
電気制御盤の展開接続図を作成するブラウザベース電気CAD（Vanilla JS + Canvas API）。
GitHub: `youichi558-collab/special-spoon` の `electrical_cad_v3/ecad_v3/`。
起動: `server.py` 経由のローカルHTTPサーバー。

## 作業フロー
Claudeが毎セッション`git clone`（`/tmp`は揮発性のため）→ コードをpush → 盛田さんがGitHub Desktopでpull → Ctrl+Shift+Rでリロードして実機テスト。
コミット前に`git config user.email/user.name`設定必須。pushは`git pull --rebase`後に実施、force push禁止。

### **【重要】mainブランチで直接作業する**（2026-09-01に明文化、盛田さん「mainで作業しろ、そういう方式」）

**作業ブランチを切ってプルリクエストを作る運用ではない。`main`に直接コミットしてpushする。**

理由: 盛田さんはGitHub Desktopでpullして実機で試す。ブランチに積むと**pullしても
反映されない**（ブランチを切り替える操作が余計に要る）。この開発は
「Claudeが直す → 盛田さんがすぐ実機で確認する」の往復で回っているので、
push即pullで届くことが前提になっている。

- セッション開始時にClaude側の指示で作業ブランチ名が指定されていても、**この方針が優先**
  （2026-09-01のセッションでは指定に従ってブランチ運用をしてしまい、盛田さんが
  pullしても変更が来ない状態を作った）
- そのため**push前に必ずテスト全本を通すこと**。mainが壊れると盛田さんの手が止まる
- 大きく壊す可能性のある変更をするときだけ、事前に相談する

**【2026-09-19・同じ失敗を繰り返した】** このセッションでも、セッション開始時の

## アーキテクチャ・仕様上の制約（実地確認済み）
- **端子データ**: シンボルの端子は`cS.terminals`（`js/symbols.js`, `conn_table.js`で参照）に一本化されている
- **接続表・端子台表**（`js/conn_table.js`）: `wire.fromElId/toElId`には頼らず、幾何学的な位置一致（許容誤差5、`CONN_TABLE_TOL`）で判定している。理由はDXFインポートで生成される配線には`fromElId/toElId`が存在しないため
- **DXFインポートの構造的制約**（`js/dxf_import.js`）: ファイル内に`ECAD_DXF_V1`または`ECAD_FRAME`という文字列が含まれる場合のみ`isOwnFile=true`となり、このCAD自身が書き出したDXFとして扱われる。外部（AutoCAD等）で作られたDXFの円形状は、junction（端子）としては復元されず、ただのcircle図形として読み込まれる。接続表・端子台表を使うには、外部DXFインポート後に手動で端子を打ち直す必要がある。これはDXFフォーマット自体の構造的限界であり、実装の不備ではない
- **Undo履歴は `pushH()`**（`edit.js`）。`pushUndo()` という関数は存在しない。
  **変更前**に呼ぶこと(現在の状態をスナップショットとして積む関数のため)
- **描画色は完全BYLAYER**。要素は個別色を持たない(`el.color`は廃止済み)。
  レイヤー名が空・未登録だと `fgC()`(ダークで#ccc=ほぼ白)になり「白く壊れて」見える。
  要素を生成するときは必ず `layer` を入れること
- **線幅は図面座標の値で、ズームで割らない**(画面表示がそのままDXFに出る設計)。
  値はJIS/ISO 128の標準9種のみ使う。任意の値は `snapLineWidth()` で丸めること。
  既定は `DEFAULT_LINE_WIDTH`(0.5)
- **プロパティパネルは「適用」で入力欄の値を要素へ丸ごと書き戻す**。
  要素に直接書き込むコードを足すときは、**入力欄の値も同時に更新**しないと
  直後の適用で空の値に上書きされる
- **シンボルパネルの実描画パス**: `renderSymFloat()` / `#sym-float-body` が実際に表示される登録済みシンボル一覧

- **DXF出力での仕様(ラベル)の扱い**（`e858918`〜）: シンボルの仕様(ラベル)は、DXF上では`INSERT`のブロック属性(ATTRIB)ではなく、独立した`TEXT`実体として出力される。そのため、TrueView/AutoCAD上でシンボルをクリックしても、仕様の文字は一緒には選択されない（別々の実体）。位置・見た目はキャンバス表示と一致する

## テストの方針（2026-08-21 追加）
`tests/` 配下に node で動くテストがある。`node tests/xxx.js` で個別に、
まとめて動かすなら `node tests/run_all.js`（.py も拾う。`for t in tests/*.js` では .py が流れない）。

**必ず js の実コードを読み込んで eval し、それを動かすこと。**
挙動を書き写した再実装をテストしても意味がない。実際、今セッションで
`pushUndo()` という存在しない関数を4箇所で呼んでいたバグを、
再実装のテストが全て通ってしまったせいで見逃した(盛田さんの実機報告で発覚)。

現在あるテスト:
- `test_part_volt.js` … コイル電圧の選択肢解析(カタログの表記ゆれ対応)
- `test_part_assign.js` … 部品DBの割り当て、グループデバイス
- `test_device_ref.js` … デバイス候補の収集と引き継ぎ
- `test_group_device.js` / `test_group_show.js` … 外形図グループのデバイス表示
- `test_line_width.js` / `test_symbol_linewidth.js` … 線幅の規格値丸め
- `test_dxf_layer.js` / `test_dxf_lineweight.js` / `test_dxf_linewidth.js` … DXF読込
- `test_aci_color.js` … ACI色変換(ACI 7の扱い)
- `test_junction_snap.js` … 端子台の8点スナップ
