# ローカルLLMを試す（実験用・本番経路には入っていない）

**このフォルダは実験。** 部品DBにも図面にも書き込まない。読むだけ。
フォルダごと消しても何も壊れない。CADの動作にも一切関係しない。

## 何のためのものか

「ローカルLLM（Ollama）がこの仕事に使えるか」を、意見ではなく**数字**で決めるため。

## なぜ「種別の分類」で試すのか

一番やらせたいのは、たぶんカタログPDFからのCSV作成（`CATALOG_STATUS.md` の作業。
目標は数万件で、人手では埋まらない）。しかし**いきなりそれを試すと採点できない。**
正解が無いので「それらしいCSVが出てきた」で終わり、使えるかどうかが分からない。

一方、部品DBには**盛田さんが付けた種別が入っている**。これは人が決めた答えなので、
採点に使える。同じ問題をモデルに解かせて突き合わせれば、
「このモデルが電気部品の型番を理解しているか」が1回で数字になる。

ここで落ちるモデルは、カタログの表を読ませても確実に落ちる（表の読み取りはこちらより
難しい）。**安く早く見切りをつけるための試験。** GPUが非力でも走る。

## 使い方

```
1) Ollamaを起動し、モデルを1つ入れる
     ollama pull qwen2.5:7b          (例。手元にあるものでよい)

2) 部品DBの場所を教える（まだなら。1回だけ）
     py ..\parts_db\parts_db.py setpath "<parts_db.jsonのパス>"

3) 走らせる
     py try_classify.py --model qwen2.5:7b --n 50
```

`--n` は問題数（既定50）。まず50で様子を見て、良さそうなら増やす。
`--model` を変えて何度か回せば、モデルごとの比較になる。
`--seed` を固定してあるので、モデルを変えても**同じ問題**が出る（比較できる）。

## 結果の読み方

**正答率だけを見ないこと。外し方を見る。** 間違えた行を全部出している。

| 外し方 | 意味 |
|---|---|
| 電磁接触器 ↔ 電磁開閉器 を混ぜる | サーマル一体かどうかを見ていない。実務では別部品（S-T21とMSO-T21）なので高くつく |
| 押ボタン系の中で細かく外す | 照光か非常停止かの区別。型番から読めないこともあり、人でも間違える部類 |
| ブレーカをPLCと答える | 型番を理解していない。ここで見切ってよい |
| 「解釈不能」が多い | 指示に従えていない。プロンプトの問題かもしれないので、モデルの能力とは分けて考える |

## 【重要】正答率が高くても、部品DBに書かせない

このプロジェクトで一番高くつく間違いは「**静かに間違ったデータが残る**」こと。
9割当たるモデルは、1割を静かに間違える。そして種別の誤りは、
盤を組む段階まで気づかれない。

実際、`HANDOFF.md` には、三菱電磁開閉器PDFのページオフセットが「+3」と
**何セッションも引き継がれた末に実は「+2」だった**という記録がある。

使うなら、**書く側ではなく疑う側**に置くのが筋が良い:

> 既存のCSVとカタログを両方読ませて、**食い違う行だけを挙げさせる。** 採否は人が決める。

間違えても実害が無く（提案が外れるだけ）、見つけたいのは
まさに「静かに間違っている行」そのものになる。

## 実験が終わったら

**このフォルダごと消すこと。** `try_classify.py` は種別コードの定義を自前で持って
いるが、種別コードの定義は元々4箇所（`PART_TYPE_CODES`/`LABELS`/`ORDER`、
index.htmlのプルダウンとCSVヘルプ）にあり、増やすときは全部を揃える決まりになっている。
ここはその5箇所目にあたるので、**残すと必ずズレる。**
残すことになった場合は、サーバー経由でJSから取る形に変えること。
