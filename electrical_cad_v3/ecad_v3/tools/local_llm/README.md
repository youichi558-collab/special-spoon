# ローカルLLMを試す（実験用・本番経路には入っていない）

**このフォルダは実験。** 部品DBにも図面にも書き込まない。読むだけ。
フォルダごと消しても何も壊れない。CADの動作にも一切関係しない。

## 何のためのものか

「ローカルLLM（Ollama）がこの仕事に使えるか」を、意見ではなく**数字**で決めるため。

## なぜ「種別の分類」で試すのか

一番やらせたいのは、たぶんカタログPDFからのCSV作成（`CATALOG_STATUS.md` の作業。
目標は数万件で、人手では埋まらない）。しかし**いきなりそれを試すと採点できない。**
正解が無いので「それらしいCSVが出てきた」で終わり、使えるかどうかが分からない。

一方、部品DBには**盛田さんが付けた種別が入っている**。これは人が決めた答えなので、
採点に使える。同じ問題をモデルに解かせて突き合わせれば、
「このモデルが電気部品の型番を理解しているか」が1回で数字になる。

ここで落ちるモデルは、カタログの表を読ませても確実に落ちる（表の読み取りはこちらより
難しい）。**安く早く見切りをつけるための試験。** GPUが非力でも走る。

## 使い方

**一番簡単なのは、`ecad_v3` フォルダの `ローカルLLMを試す.bat` をダブルクリック。**
（`start.bat` と同じ場所にある。どのフォルダにいるかを気にしなくてよい）

コマンドから使う場合、**cdは不要**。`ecad_v3` から直接呼べる:

```
py tools\local_llm\try_classify.py --model qwen2.5:7b --n 20
```

事前に1回だけ、部品DBの場所を教えておく:

```
py tools\parts_db\parts_db.py find        ← 場所が分からなければ探す
py tools\parts_db\parts_db.py setpath "<出てきたパス>"
```

**`--model` は省略してよい。** 省略すると、Ollamaに入っているモデルを一覧表示する。
1つしか入っていなければ、そのまま実行する。

```
> py try_classify.py
Ollamaに入っているモデル:
  qwen2.5:7b
  llama3.1:8b

どれかを --model に指定してください。例:
  py try_classify.py --model qwen2.5:7b --n 50
```

### 「モデル名」とは

Ollamaは入れたモデルに名前を付けて管理している。`ollama list` の **NAME列**がそれで、
`--model` にはこれを渡す。

```
> ollama list
NAME                ID              SIZE      MODIFIED
qwen2.5:7b          845dbda0ea48    4.7 GB    3 days ago
```

`qwen2.5` のようにタグ（`:7b`）を省いて指定してもよい。
一意に決まればそのまま実行する。

### 何も入っていない場合

軽い順に、例:

| コマンド | 目安 | 用途 |
|---|---|---|
| `ollama pull qwen2.5:3b` | 約2GB | 一番軽い。まず動くか見る用 |
| `ollama pull qwen2.5:7b` | 約5GB | 日本語がまとも。本命 |
| `ollama pull llama3.1:8b` | 約5GB | 比較用 |

GPUが非力でも、3bなら動くことが多い（遅いだけ）。まず3bで通してから7bへ。

### 小さいモデルは、聞いた言語と違う言語で返すことがある

盛田さんの実機で `qwen2.5:3b` に日本語で「動いてる？」と聞いたところ、
**中国語で返ってきた**（小さい中国語圏モデルではよくある。故障ではない）。

この試験で測りたいのは「電気部品の型番を理解しているか」であって
「何語で答えるか」ではないので、プロンプトは英語で書き、
**英字の種別コードだけを返すよう指示**してある。
説明文が何語で付いてきても、`normalize()` がコードを拾う。

### 遅いのか、壊れているのか

**大きいモデルはGPUに載り切らないとCPUに落ちる。** Ollamaはこれを黙ってやるので、
1問に何分もかかる状態になり、見た目は固まったのと区別が付かない。

スクリプトは本番の出題前に**1問だけ投げて速さを測り**、実行場所と見込み時間を出す:

```
疎通確認中(最初の1問。モデルの読み込みを含むので時間がかかります)...
  実行場所: 100% CPU
  ⚠ GPUに載り切っていません。この状態は「壊れている」のではなく「遅い」だけです
  1問目: 6秒 → 50問で概ね 5分 の見込み
```

`ollama ps` の PROCESSOR 列と同じ情報。`100% GPU` なら実用になる。
CPUが混ざるならVRAM不足なので、小さいモデルに替える。

**モデルの大きさの目安**（GPUに載せるにはこれ以上のVRAMが要る）:

| モデル | SIZE | 必要なVRAMの目安 |
|---|---|---|
| 3B級 | 約2GB | 4GB〜 |
| 7〜8B級 | 約5GB | 8GB〜 |
| 26B級 | 約18GB | 20GB〜 |

### オプション

`--n` は問題数（既定50）。まず50で様子を見て、良さそうなら増やす。
`--model` を変えて何度か回せば、モデルごとの比較になる。
`--seed` を固定してあるので、モデルを変えても**同じ問題**が出る（比較できる）。

## 結果の読み方

**正答率だけを見ないこと。外し方を見る。** 間違えた行を全部出している。

| 外し方 | 意味 |
|---|---|
| 電磁接触器 ↔ 電磁開閉器 を混ぜる | サーマル一体かどうかを見ていない。実務では別部品（S-T21とMSO-T21）なので高くつく |
| 押ボタン系の中で細かく外す | 照光か非常停止かの区別。型番から読めないこともあり、人でも間違える部類 |
| ブレーカをPLCと答える | 型番を理解していない。ここで見切ってよい |
| 「解釈不能」が多い | 指示に従えていない。プロンプトの問題かもしれないので、モデルの能力とは分けて考える |

## 実測（2026-09-02・盛田さんのPC）

`qwen2.5:3b` で **13/20 = 65%**、1件0.7秒（100% GPU）。
605件の全件でも約7分なので、**速度は問題にならない**。

問題は外し方だった。誤答7件のうち「分かりません」と言えたのは1件だけで、
**残り6件は自信を持って別のコードを答えた**（`MR-J5-350G4`(サーボアンプ)を
サーボモータ、`KV-C32XTD`(PLC増設ユニット)をインバータ、など）。

出力の下の方に、この観点の集計を出している:

```
誤答の内訳: 自信を持って間違えた 6件 / 答えられなかった 1件
  ⚠ 間違えるときに黙ってそれらしい答えを返している。
    この性質のモデルに部品DBを書かせてはいけない
```

**ここが一番大事**。間違えたときに黙ってそれらしい答えを返すのか、
答えられないと分かるのかで、使える用途がまるで変わる:

- 自信を持って間違える → 人が全件を見直すことになり、**自動化の意味が無い**
- 答えられないと分かる → **「怪しい行だけ人が見る」使い方ができる**

### 種別ごとの出来も見ること

全体の正答率だけでは判断を誤る。`付属品`・`PLC増設ユニット` のように
**型番だけでは人でも判別できない**区分が混ざっているため、
そこの失点と、実務で効く区分（サーボアンプ／サーボモータ等）の失点は意味が違う。

```
種別ごとの出来（出題数の多い順）:
  電磁接触器               7/8   #########
  ブレーカ                5/6   ########
  PLC増設ユニット           0/2
  ※ 出題数が1〜2件の行は、当たり外れの運の範囲
```

## 【重要】正答率が高くても、部品DBに書かせない

このプロジェクトで一番高くつく間違いは「**静かに間違ったデータが残る**」こと。
9割当たるモデルは、1割を静かに間違える。そして種別の誤りは、
盤を組む段階まで気づかれない。

実際、`HANDOFF.md` には、三菱電磁開閉器PDFのページオフセットが「+3」と
**何セッションも引き継がれた末に実は「+2」だった**という記録がある。

使うなら、**書く側ではなく疑う側**に置くのが筋が良い:

> 既存のCSVとカタログを両方読ませて、**食い違う行だけを挙げさせる。** 採否は人が決める。

間違えても実害が無く（提案が外れるだけ）、見つけたいのは
まさに「静かに間違っている行」そのものになる。

## 実験が終わったら

**このフォルダごと消すこと。** `try_classify.py` は種別コードの定義を自前で持って
いるが、種別コードの定義は元々4箇所（`PART_TYPE_CODES`/`LABELS`/`ORDER`、
index.htmlのプルダウンとCSVヘルプ）にあり、増やすときは全部を揃える決まりになっている。
ここはその5箇所目にあたるので、**残すと必ずズレる。**
残すことになった場合は、サーバー経由でJSから取る形に変えること。
