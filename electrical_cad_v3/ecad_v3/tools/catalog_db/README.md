# カタログDB

各メーカーのカタログから起こした部品データ（将来数万件）を検索するための仕組み。
**CADの部品DB（盛田さんが手で育てる `parts_db.json`、数千件）とは別物。**

```
Google Drive「カタログDB」フォルダ         ローカルPC
  mitsubishi.csv  ─┐                    ┌─ catalog.sqlite3（生成物・消してよい）
  fuji.csv        ─┼─ catalog_db.py ───┤
  omron.csv       ─┘   （構築＋検索）    └─ CADの検索欄／他ツール
  ...
```

- **CSVが原本。** Drive上にメーカーごと1ファイル。Drive for Desktopで同期されるので、ただのファイルとして読む（Drive APIは使わない）。
- **SQLiteは生成物。** ローカルに作られる。CSVから毎回作り直せるので、消しても失われるものは無い。**Driveには置かない**（バイナリの同期が現実的でないため）。
- **Gitとは組み合わせない。** カタログデータはリポジトリに入れない。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `catalog_db.py` | **本体。** CSV読込・SQLite構築・検索。サーバー機能は持たない |
| `catalog_server.py` | 他ソフトから使いたいときだけ起動する独立HTTPサーバー（**普段は不要**） |
| `append_catalog.py` | Cowork/Claudeがカタログの行を追記するための専用スクリプト |

`ecad_v3/server.py` は `catalog_db.py` を直接importして使う。
→ **盛田さんは今まで通り `start.bat` を起動するだけでよい。常駐サーバーは増えない。**

## 初回セットアップ

CADの「部品登録」パネル →「カタログDBから探す」欄で設定する。パスの手入力は不要。

「📁 フォルダを選ぶ」を押すと、ドライブ一覧が出る。
ドライブ → フォルダ と辿って「このフォルダに決定」を押すだけ。
各フォルダのCSV数が表示されるので、目的のフォルダかどうか分かる。

設定後も「📁 フォルダを変更」でいつでも選び直せる。

ブラウザはセキュリティ上フォルダの絶対パスをJSに渡さない（`webkitdirectory` でも
フォルダ名しか取れない）ため、サーバー側でドライブ／フォルダを列挙して
画面上でクリックして辿る方式にしている。

コマンドで設定することもできる:

```
py catalog_db.py setdir "G:\マイドライブ\claude\部品カタログ\カタログDB"
py catalog_db.py build
```

ドライブレターは環境によって I: / G: と変わるため、パスは設定値として保存している。
別のPCで使うときはそのPCで設定し直す（DBもそのPCで自動生成される）。

## 日常の使い方

CADの「部品登録」パネルの「カタログDBから探す」で型番を検索し、
必要なものだけ「部品DBへ」を押す。**カタログ全数を部品DBに流し込むことはしない。**

CSVが更新されていれば検索時に自動で取り込む（変更が無ければ何もしないので重くならない）。
明示的に作り直したいときは「再構築」ボタン、またはコマンドで:

```
py catalog_db.py build --force
```

## Coworkがカタログを追記するとき

ファイル全体を読み込まず、末尾に追記するだけ:

```
py append_catalog.py "<カタログDBフォルダ>" mitsubishi < 新しい行.csv
```

- 8列であることを検証してから書き込む。**1行でも不正なら何も書き込まない**
- 仕様値の中の生カンマ（例 `AC200V(三相200~240V,50/60Hz)`）は列ズレの原因になるので拒否する。`/` や `・` に置き換えること
- 価格らしき記載も拒否する（価格データは登録しない）
- **重複チェックはしない。** 同じ型番が複数回書かれていてもSQLite構築時に後勝ちで正規化される。CSVは「追記のみ・重複可」、正規化はDB側、という役割分担

## 他のソフトから使う

**Pythonから:**

```python
import catalog_db
db = catalog_db.CatalogDB()
db.ensure_built()
rows = db.search('MR-J5', maker='三菱電機')
```

**他言語・別プロセスから:** このときだけHTTPサーバーを起動する。

```
py catalog_server.py            # 既定ポート 8090
```

```
GET /search?q=MR-J5&maker=三菱電機&limit=50
GET /get?ref=MR-J5-40G
GET /stats
GET /rebuild
```

## 他のPCで使う

そのPCにDrive for Desktopが入っていれば、`setdir` して `build` するだけ。
各PCが自分のローカルにDBを作る。ネットワーク設定も常駐サーバーも要らない。

## CADだけ動かしたいPCでは

**カタログDBが無くてもCADは通常通り動く。**
このフォルダごと無くても `server.py` は起動し、作図・DXF入出力・帳票はすべて従来通り。
検索欄が「未導入です」と表示されて使えなくなるだけ。

Driveが同期していない場合も、前回構築したDBがあればそのまま検索できる
（最新CSVが反映されていない旨の警告が出る）。

## やめたくなったら

1. このフォルダ `tools/catalog_db/` を削除
2. ローカルのデータフォルダを削除
   - Windows: `%LOCALAPPDATA%\ecad`
   - それ以外: `~/.local/share/ecad`

これで元の状態に戻る。**CSV原本はDriveに残るので中身は失われない。**
`index.html` の検索欄と `js/ui.js` の `catalog*` 関数を消せば表示も消える。

## 実測（参考）

| 件数 | 構築 | 検索 | DBサイズ |
|---|---|---|---|
| 605件（現行データ） | 0.02秒 | 1ms未満 | 約0.5MB |
| 50,000件（想定最大） | 1.1秒 | 25ms | 約38MB |

変更なしと判定して再構築を省く処理は0.7ms。起動が重くなることはない。
